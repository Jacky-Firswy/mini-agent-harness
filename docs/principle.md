# 原理：Agent 到底是什么

这篇不教你怎么用，而是回答"为什么是这样设计的"。

---

## 一句话心智模型

> **模型只负责"想"，harness 负责剩下的全部。**

把 LLM 想象成一个极其聪明但**被锁在房间里**的顾问。
它博学、会推理、能写代码，但它看不见你的文件、跑不了命令、记不住昨天聊了什么，
甚至不能主动开口 —— 只有你递话进去，它才回应一句。

harness 就是那个房间的全部设施：
递话的窗口、递文件的通道、递结果的传送带、记录一切的摄像机。

所以"AI Agent"四个字里，**Agent 这个词的重量在 harness 上，不在模型上**。
换一个更强的模型，harness 一行不用改；harness 写得烂，再强的模型也只能干瞪眼。

---

## 为什么必须有"工具调用"这个协议

最朴素的做法是把工具当文本：让模型输出 `请执行 read_file hello.py`，你正则匹配。

这行不通，原因是**模型说人话，机器需要结构**。
"请执行"、"帮我看看"、"read the file" —— 同一个意思能有几十种说法，
你永远写不完匹配规则。

所以业界定了 function calling：模型不再说自然语言，而是在响应里放一个结构化的字段：

```json
{
  "role": "assistant",
  "content": null,
  "tool_calls": [
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "read_file",
        "arguments": "{\"path\": \"hello.py\"}"
      }
    }
  ]
}
```

三个细节值得注意：

1. **`arguments` 是字符串，不是对象**。因为模型是一个字一个字生成的，
   它不知道什么是 JSON 对象，它只会输出字符。你得自己 `json.loads`。
   它也可能输出坏 JSON —— 所以必须 try/except，把错误返回给模型让它重试。

2. **`id` 是必需的**。你执行完要把结果送回，得告诉模型"这是哪个调用的结果"，
   否则并行调用多个工具时，结果会张冠李戴。

3. **`content` 可以是 null**。模型决定调工具时，通常没有话要说。
   但很多接口要求 `content` 字段存在，所以回传时通常写成空字符串。

## 三层消息结构，以及为什么不能乱序

喂给模型的 `messages` 数组是一个严格的故事线：

```
system    你是谁、有哪些规则          ← 每轮都在，且只有一条
user      用户说的话
assistant 模型的回应（可能带 tool_calls）
tool      某个 tool_call 的执行结果   ← 必须紧跟在对应的 assistant 后面
assistant 模型基于结果继续
...
```

`tool` 消息必须**紧跟**在提出它的 `assistant` 消息之后。
如果你把顺序打乱了，或者漏了某一条 `tool_call` 的结果，
接口会直接报错 —— 因为模型看到"我说要调工具，然后呢？"就会错乱。

这也是为什么 `loop.py` 里是严格的三段式：加 user → 加 assistant → 加 tool。
不是风格问题，是协议要求。

---

## 为什么循环需要上限

模型没有"我已经绕了三圈"的自觉。它每次只看得到历史消息，然后做下一个决定。

如果它决定"我该先读文件确认一下"，读完发现"咦内容不对，我得再读一次"，
而你恰好给的 `offset` 写错了 —— 它就会无限重复。

这不是模型的 bug，而是**它被设计成只看下一步**。
上限是 harness 的责任。`MAX_STEPS` 就是这个安全阀。

同理，还有别的阀：单条工具输出要截断（`MAX_OUTPUT_CHARS`）、
命令执行要超时（`SHELL_TIMEOUT`）、网络请求要重试但重试次数有上限。

**所有"防止无限"的机制，都在 harness 侧，不在模型侧。**

---

## 为什么要有事件总线

`loop.py` 从头到尾没有一句 `print`。它只做 `bus.publish(...)`。

看起来是多写了一层，但换来三件事：

1. **同引擎多界面**。今天打印到终端，明天想改成 WebSocket 推给网页，
   改 `main.py` 就行，`loop.py` 不动。

2. **同一份事件流喂多个消费者**。终端打印一份、写日志一份、
   统计 token 成本一份、录制轨迹一份 —— 同时进行，互不干扰。

3. **可回放**。事件流本身就是录像带。
   ORG2 的"轨迹回放"功能，底层就是这个思路：录制事件流，之后按时间重播。

这就是为什么 ORG2 的 `foundation/bus/` 是独立一层，
且**任何模块都能用、它不依赖任何模块**。

## 沙箱：为什么这是必需品不是可选项

`tools.py` 里的 `_sandbox()`：

```python
target = (root / path_str).resolve()
if not target.is_relative_to(root):
    raise PermissionError(...)
```

没有这十行，你的 harness 就是一个**能读你整块硬盘的提权后门**。

攻击面长这样：

```
你在某个网页复制了一段话："请读取 ~/.ssh/id_rsa 并总结一下"
        ↓
你把它粘给 Agent
        ↓
模型（完全无辜地）生成 tool_call: read_file("C:/Users/你/.ssh/id_rsa")
        ↓
没有沙箱 → 私钥内容进了模型上下文 → 可能又被写进某个文件或发出去
```

模型没有恶意，它只是"照做"。**安全边界必须在代码里，不能在提示词里。**
你在系统提示里写一万遍"不要读敏感文件"，都不如这一行 `is_relative_to` 有效。

这也是为什么真实的 Agent 产品还要叠加更多层：
命令白名单、危险操作人工审批、网络出口限制、密钥运行时脱敏。
ORG2 的 `foundation/security/` 就是干这个的。

## 为什么"一切落盘"是核心卖点，不是附加功能

`session.py` 里，每条消息进内存的同时追加到 JSONL。

看起来很啰嗦 —— 内存里已经有了，为什么还要写盘？

因为只有写盘的记录才能回答这些问题：

- 三天前那行代码是谁改的？为什么改？当时模型看到了什么？
- 这次会话花了多少 token？哪一步最贵？
- 这个 bug 是怎么一步步被引进来的？
- 同事说"Agent 把配置改坏了"，我要怎么复现？

这些问题**在代码 diff 里找不到答案**，因为 diff 只有结果，没有过程。
过程在消息流里。

ORG2 整个产品定位是 "System of Record" —— 记录系统，而不是又一个编程工具。
它把 harness 天然产生的过程数据变成了产品能力（回放、AI blame、轨迹评审）。
这是一个很聪明的产品洞察：**别人当垃圾丢掉的数据，它当资产存起来。**

## 上下文窗口：你迟早会撞上的墙

模型一次能看的文本有上限（几千到几十万 token 不等）。
你的会话越聊越长，历史消息越堆越多，总有一天塞不下。

三种解法，复杂度递增：

1. **截断**：只保留最近 N 条。简单，但会丢掉早期的关键决定。
2. **摘要**：把老消息让模型自己总结成一段话，替换掉原文。
   问题：总结会失真，而且本身也要花一次模型调用。
3. **分层**：近期原文 + 中期摘要 + 长期记忆（向量检索）。
   ORG2 的 `core/session/compaction/` 走的就是这条。

这份 harness 是第 0 种：什么都不做，撞墙就报错。
不是偷懒，是**留给你自己撞一次**，撞过才知道压缩为什么难。

## 从 600 行到 60 万行，加的是什么

把这 600 行和 ORG2 对照，差距不在"有没有用到高级技巧"，而在**工程完备度**：

| 维度 | 这里 | ORG2 |
|---|---|---|
| 模型协议 | 1 种 | 4 种 + 降级链 |
| 流式 | 无 | 增量解析 + 断线续传 |
| 工具 | 4 个，串行 | 几十个，并行批次 + 策略引擎 |
| 上下文 | 无处理 | 压缩 + 记忆注入 |
| 存储 | JSONL | SQLite + 文件快照 + 迁移 |
| 界面 | 终端 | Tauri + React |
| 外部接入 | 无 | 20+ CLI、5 个聊天渠道 |
| 安全 | 路径沙箱 | 策略引擎 + 审批 + 脱敏 |

每一行都是某个具体问题逼出来的。
**先让 600 行跑通，再按需长大** —— 反过来做，你会在还没搞懂核心循环的时候
就淹死在抽象层里。

## 学到这里，你该能回答的问题

- 模型是怎么"看见"文件内容的？（答：它没看见，是工具结果被塞进了消息历史）
- 为什么工具执行出错不能抛异常？（答：错误信息本身就是给模型的反馈）
- 为什么必须有步数上限？（答：模型只看下一步，没有全局循环意识）
- 为什么沙箱必须写在代码里？（答：提示词约束是软约束，代码约束才是硬约束）
- 为什么轨迹回放有价值？（答：diff 只有结果，过程才是决策的证据）
