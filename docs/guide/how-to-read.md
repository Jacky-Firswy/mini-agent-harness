# 这本书怎么读

## 先做一次自我定位

这本书有 20 多个章节。**没有人需要一次读完。** 先对号入座，然后只走你那条路线。

=== "路线 A：我只想弄懂概念"

    你不需要会写代码，也不需要装任何东西。目标是把 Agent 这套东西的**直觉**建立起来。

    按这个顺序读，大约 90 分钟：

    1. [ORG2 到底是个什么系统](what-is-org2.md) — 建立整体印象
    2. [Agent 内核](../core/agent-kernel.md) — 理解那个"循环"
    3. [一条消息的旅程](../core/message-journey.md) — 看它怎么跑一圈
    4. [事件流](../core/event-stream.md) — 理解你在屏幕上看到的东西是怎么来的
    5. [工具系统](../core/tools.md) — 理解 Agent 为什么能"动手"

    **可以跳过**：Provider 层、持久化、前端与 Tauri、建造史里所有提交号。

=== "路线 B：我想照着搭一个"

    你已经在写代码了（或者正准备写）。目标是**能跑起来**，然后逐步加厚。

    顺序：

    1. [Agent 内核](../core/agent-kernel.md) — 先想清楚要几个模块
    2. [一条消息的旅程](../core/message-journey.md) — 对着画出你自己的调用链
    3. [工具系统](../core/tools.md) — 照着实现 `Tool` 抽象和注册表
    4. [回合执行器](../core/turn-executor.md) — **重点**：这是最容易低估的地方
    5. [事件流](../core/event-stream.md) — 一旦你加界面，这章立刻变成刚需
    6. [我自己的 harness 对照](../appendix/my-harness.md) — 检查你走到哪一步了

=== "路线 C：我要改 ORG2 的代码"

    你要往真实仓库提 PR。目标是**不踩规矩**。

    顺序：

    1. [五层架构规则速查](../appendix/architecture-rules.md) — 先背下来
    2. [Agent 内核](../core/agent-kernel.md) — 弄清楚每层放什么
    3. [会话与状态](../core/session.md) — 18 个子模块的分工表
    4. [Provider 层](../core/providers.md) — 那条"不许字符串比较"的硬规矩
    5. [工具系统](../core/tools.md) — 加工具的标准动作
    6. [测试与自进化](../data/testing.md) — 改完怎么验证

## 这本书的写法，有四个刻意的选择

### 一、先讲"为什么必须存在"，再讲"它长什么样"

大多数技术文档是这个顺序：先给你一个 API 列表，再讲用法。

这本书反过来。每一节的开头先回答一个问题：**如果不做这个东西，会出什么事？**

举一个真实例子。第 [事件流](../core/event-stream.md) 章一开头不是讲 `StreamingBuffer` 的字段，而是先给你看旧方案：

```text
旧：Rust → delta → WebSocket → TS 累加器 → 状态库 → 界面
新：Rust → delta → StreamingBuffer → 完整事件 → 事件库 → WebSocket → 界面
```

然后问一句：**为什么"TS 累加器"这一环必须被删掉？** 因为在浏览器里累加流式文本，一旦断线重连、或者用户切走页面再回来，累加器里的半截内容和数据库里的内容就对不上了。

先有痛感，再看方案，你才会记住。

### 二、小功能点单独讲，不打包进"等等"

你要求"包括小功能点"。所以像这些东西都有独立小节：

- token / 成本是怎么记账的（`usage_accumulator.rs`）
- 模型输出被截断了怎么办（`length_recovery.rs`）
- 往对话里怎么塞一张截图（`screenshot.rs`）
- 工具调用撞名了怎么处理（MCP 工具与内置工具冲突）
- 一个回合里模型"文本→工具→文本"交替时，事件 id 为什么会撞车

这些听起来琐碎，但**正是它们区分了"玩具"和"产品"**。

### 三、源码位置一律标注

每一节末尾会有这样一行：

<p class="src-path">源码：src-tauri/crates/agent-core/src/core/turn_executor/mod.rs</p>

你可以拿着路径去 GitHub 上核对。**不要无条件相信这本书** —— 包括我。

### 四、推断会被显式标记

!!! warning "⚙️ 这是推断，不是源码原文"
    当出现这个框，说明这句话是我根据代码形态推测的，源码或文档里并没有明写。它有可能是错的。你可以直接来问我依据是什么。

## 遇到读不懂的地方怎么办

**直接问我。** 这是这本书的设计前提之一。

流程是这样的：

1. 你读到某一段，觉得不明白，或者想深入某个细节
2. 你来问我（在对话里说"这本书的 X 章我没看懂 Y"）
3. 我解释完之后，会反问你一句：**要不要把这段解释补进书里？**
4. 你说要，我就把它写成正式章节，并打上版本号

这样你的每一个困惑，都会变成这本书的一个增量。**这本书是跟你一起长出来的。**

详细的批注写法见 [怎么写批注](../notes/how-to-annotate.md)。
