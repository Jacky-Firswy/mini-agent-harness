# 怎么写批注

## 三种标记

这本书用三个视觉标记来区分三类内容。**都是普通 Markdown**，没有插件依赖，`git diff` 能看，能回滚。

### 1. 📝 我的批注 —— 绿色

用于你自己的笔记、疑问、心得。

```markdown
!!! quote "📝 我的批注 · 2026-11-06 · v0.1"
    这里写你的笔记。可以多行。
    缩进四个空格即可。
```

效果：

!!! quote "📝 我的批注 · 2026-11-06 · v0.1"
    这里写你的笔记。可以多行。

### 2. 🆕 版本补充 —— 金色

用于"后来补进文档的内容"。**标题里必须带版本号**。

```markdown
!!! success "🆕 版本补充 · v0.2 · 2026-11-06"
    这一段是后来补的。版本号让你能看出这本书的生长轨迹。
```

效果：

!!! success "🆕 版本补充 · v0.2 · 2026-11-06"
    这一段是后来补的。

### 3. ⚙️ 推断存疑 —— 橙色

用于"这是我的推断，不是源码实证"。**看到这个框，你可以怀疑它。**

```markdown
!!! warning "⚙️ 这是推断，不是源码原文"
    这句话是我根据代码形态推测的，源码里没有明写。
```

## 完整流程：提问 → 回答 → 补进文档

这是这本书设计的核心循环。

```text
① 你读到某一段，有疑问
        ↓
② 你来问我（任意方式描述）
        ↓
��� 我解释
        ↓
④ 我问你：「要不要把这段补进书里？」
        ↓
⑤ 你说要 → 我写进对应章节，打上 🆕 版本补充 框
        ↓  同时更新「批注汇总」页的版本表
⑥ 你说不用 → 我只在对话里解释，文档不动
```

**这个循环的意义**：你的每一个困惑都会变成文档的一个增量。**这本书是跟你一起长出来的**，不是一次性写完就冻住的。

## 版本号规则

| 变化 | 版本号 |
|---|---|
| 新增一整章 | 次版本号 +1（v0.1 → v0.2） |
| 补充某一段的解释 | 次版本号 +1 |
| 修正错别字 / 链接 | 修订号 +1（v0.1 → v0.1.1） |
| 全书结构重排 | 主版本号 +1（v0 → v1） |

**当前版本：v0.1**（2026-11-06 首次成稿）

## 版本表记在哪

记在两处：

1. **每个 🆕 框的标题里** —— 让人知道这一段是什么时候补的
2. **[批注汇总](my-notes.md) 顶部的版本表** —— 让人知道整本书的演化

## 怎么写你自己的笔记

### 直接改文件

文档是纯 Markdown，你可以直接用任何编辑器打开 `docs/` 下的文件。

**推荐做法**：在每章末尾留的那个批注位里写。

### 用网站的编辑按钮

如果启动的是 `mkdocs serve`（本地预览），Material 主题支持"编辑此页"按钮 —— 但要额外配置 `edit_uri` 指向你的仓库。当前没配。

### 一条建议

**不要只写"不懂"。** 写具体一点：

- ❌ "事件流看不懂"
- ✅ "为什么 5 秒超时是合理的？如果模型思考很久但一直不输出，会不会被误判成结束了？"

**越具体的问题，答案越能变成文档的一个好章节。**

## 重建网站

改完 Markdown 后，本地预览会自动刷新（`mkdocs serve` 有热重载）。

如果是要生成静态文件：

```bash
python -m mkdocs build
```

产物在 `site/` 目录。**`site/` 已在 `.gitignore` 里**，因为它是生成物。

## 发布到公网（手机也能看）

站点已经托管在 GitHub Pages：

**https://jacky-firswy.github.io/mini-agent-harness/**

改完文档后，一条命令就能更新线上版本：

```bash
git add docs mkdocs.yml
git commit -m "文档：补充 xxx"
git push origin main
python -m mkdocs gh-deploy --strict
```

最后那条 `gh-deploy` 会构建、推到 `gh-pages` 分支，然后 GitHub Pages 自动生效（大约 1~3 分钟）。

### 为什么不用 GitHub Actions 自动发布

本来配了一个工作流，push 就自动构建。但它启动即失败，报错是：

```text
The job was not started because your account is locked due to a billing issue.
```

**这是账号计费问题，不是仓库配置问题。** 所以现在的流程是手动跑 `gh-deploy`。等计费问题解决后，可以再把工作流加回来。

### 本地局域网访问（手机同一 WiFi）

如果只是临时给同一 WiFi 下的手机看，可以不推公网：

```bash
python -m mkdocs serve -a 0.0.0.0:8000
```

然后手机访问 `http://<本机局域网IP>:8000/`（本机 IP 用 `ipconfig` 查）。

**`-a 0.0.0.0` 是必须的** —— 默认的 `127.0.0.1` 是回环地址，只有本机能连，手机永远打不开。另外 Windows 防火墙要放行这个端口，否则也会被拦住。
