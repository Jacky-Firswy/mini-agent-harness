    Agent 内核¶

    先说结论¶

    "内核"是一个没有界面的循环体。 它只做四件事：

    1. 把对话历史发到一个模型 API
    2. 看模型是否要求调用工具
    3. 如果要求，执行工具，把结果追加进历史
    4. 回到第 1 步，直到模型不再要求工具

    就这样。整个 agent-core 包（几十万行）都是在这个循环上加肉。

    为什么必须"没有界面"¶

    这是第一个设计理念，值得停下来想清楚。

    假设内核直接操作界面：它知道有一个叫"发送按钮"的东西，知道消息要显示在一个叫"气泡"的组件里。会发生什么？

    第一，你没法从别的入口叫它。 如果消息是从 Telegram 来的，没有"气泡组件"，内核就废了。

    第二，你没法测试它。 测试需要启动整个界面。

    第三，也是最重要的：你会开始相信界面里的状态是真实的。 而界面的状态是易失的 —— 用户切个标签页、刷新一下、断个网，就没了。

    所以 ORG2 的做法是：内核只认数据，不认像素。

    内核这边的原话（ARCHITECTURE.md 第 1 节）：

    agent_core is the headless brain of an AI coding agent. It runs inside the Tauri Rust process, has no UI of its own, and exposes everything to the frontend via Tauri commands in state/commands/.

    翻译：agent_core 是一个 AI 编程 Agent 的无头大脑。它跑在 Tauri 的 Rust 进程里，自身没有界面，所有能力通过 state/commands/ 里的 Tauri 命令暴露给前端。

    🆕 版本补充 · v0.2 · 2026-11-07 · 把上面三条理由串起来

    上面三条只有论断，没有展开。这里补一个统一的视角。

    不是"专注"，是"没有那条依赖边"¶

    最容易犯的误读是把这件事理解成：「内核知道界面的存在，只是选择不去理会它」。

    如果真是这样，那内核里写一句 if (界面有焦点) { ... } 就该是允许的，只要"别太依赖"就行。

    事实恰恰相反。 那一行代码永远写不进去 —— Rust 里跨 crate 使用必须先声明依赖，没声明就是编译错误。foundation/bus/mod.rs 的注释说得很死：

    has no compile-time back-edge into app

    编译期没有一条反向依赖指向界面层。

    所以准确的说法不是"内核不去看界面"，而是：内核不认识界面。它甚至没有能力认识。

    "专注"这个框架骗人的地方在于 —— 程序不会分心。它没有注意力可以被干扰。真正在防的不是"分心"，而是依赖传染：内核一旦依赖界面，那么"所有使用内核的地方"就等于依赖了界面。

    这也正是 五层结构与依赖规矩 里那句话的意思：一个底层工具为了图方便直接去读上层状态，明天你要把它搬走，就会发现它拖着一整条依赖链。

    三条理由其实是同一条¶

    它们都在说同一件事：内核不得依赖任何消费者。

    书里的理由 在防的"消费者"
    ① 从别的入口叫不了它 消费者种类多：桌面、Telegram、CLI
    ② 没法测试它 消费者可以没有人
    ③ 会相信界面里的状态 消费者手里的状态不可信

    测试本身也是一种"消费者"—— 它要驱动内核，但不显示任何东西。

    三条各自的补充¶

    ① 比"可包装"更强：内核是可剥离的。 源码注释提到 "any future extracted agent-core crate"，他们把「将来把内核整个抽成独立 crate」当成明确的设计目标。这不是弹性，是可剥离。

    ② 主体要反过来：不是"内核去执行测试"，是"测试去执行内核"。 这个区别不是抠字眼 —— 之所以测试能调用内核，是因为内核是个库，不是个应用。如果内核自己带界面（自己是个能双击运行的程序），测试就没法把它当函数调。

    ③ 是三条里最准的：独立存在。 书里的原话是「内核只认数据，不认像素」，以及 事件流 那章的「界面是最后一个环节，而且可以缺席」。"可以缺席"是对"独立存在"最严格的定义 —— 不是"界面在的时候也能工作"，而是"界面不在，它照样跑完，数据照样落库"。

    一句修正后的总结¶

    内核不依赖任何界面，不是因为它忽略界面，而是因为它根本不该有指向界面的依赖边。这样它才能被多种入口调用、能被测试直接驱动、能在界面缺席时正常工作 —— 而这三件事都不是"更专注"带来的，是"没有那条依赖边"带来的。

    顺带纠正一个可能的误解¶

    "没有界面"不等于"不做界面测试"。ORG2 有三个专门做测试的 crate（e2e-test、test-runner、test-helpers），见 测试与自进化。

    准确的层级是：内核逻辑可以脱离界面测，E2E 再叠在上面测"用户真的看到了吗"。如果内核和界面焊死，第一层就没了，只剩又慢又脆的 E2E。

    这个循环外面套着什么¶

    这一页只讲内核本体。内核外面还套着五层结构，以及层与层之间的依赖规矩 —— 那部分单独成页，见 五层结构与依赖规矩。

    分开放的理由：那五层讲的不是"内核在做什么"，而是"代码怎么分家、谁许 import 谁"。两件事混在一章里，读的时候容易分不清哪句在讲机制、哪句在讲纪律。

    本章要点¶

    1. 内核 = 没有界面的循环体：发历史 → 看要不要工具 → 执行工具 → 回第 1 步
    2. 内核只认数据，不认像素
    3. "没有界面"不是"忽略界面"，而是没有指向界面的依赖边；内核连认识界面的能力都没有
    4. 三条理由防的是同一个东西——内核不得依赖任何消费者（种类多 / 可以没人 / 状态不可信）
